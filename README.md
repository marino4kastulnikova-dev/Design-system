# BaaS Web Design System — documentation portal

A documentation site for the BaaS web design system, for designers and developers. It is a component explorer in the
spirit of Storybook: you can look up a component, try it live, see every variant and state, read its documentation, and
copy tokens and code.

The source of truth is the Figma file
[Baas-Web-Design-System](https://www.figma.com/design/AfiYjkdFU2Flc69Qgpw7yv/Baas-Web-Design-System). The portal does not
change the Figma file and does not sync with it automatically (see [Updating from Figma](#updating-from-figma)).

> **Status: work in progress, local only.** Every component in Figma is still marked DRAFT, and there is no production
> component package yet. The components on this site are a **portal implementation, pending developer validation**:
> they follow the Figma specification but are not a production API.

## What is in it

| Section | Content |
| --- | --- |
| **Overview** | Purpose of the system, how to read the labels, coverage. |
| **Foundations** | **Colour:** 187 variables, with primitive → semantic aliases kept. **Icons:** all 101 glyphs, with filter, size, colour and copy-name. Typography, Dimensions, Radius, Borders and opacity, Gradients, Shadows and glass are listed as token tables for now. |
| **Components** | 39 pages, one per Figma page (48 components and component sets). The catalog has search and filters by category and status. |
| **Search** | Search across components, documentation text and token names. Press `/` to open it. |
| **Token export** | `public/tokens/tokens.css` (CSS custom properties) and `public/tokens/tokens.json` (Design Tokens format). The schema is in `docs/token-schema.md`. |

Each component page has:

- **Live preview.** It runs in an isolated frame, with controls for the real Figma properties, background and viewport switches, Reset, and a code snippet that follows the controls.
- **Variants and states.** A matrix of every variant and state in the Figma component set: hover, focus, disabled, loading, checked, selected, error and so on.
- **Documentation.** Text from the Figma documentation frames: composition, usage, design properties, tokens, implementation API, accessibility, and edge cases.
- **Interactions.** Real behaviour where it exists: dropdown selection, modal open and close with a focus trap, pagination, row selection, copying, sidebar collapse.

All sample data (names, IBANs, amounts, addresses) is synthetic.

### Labels used on the site

| Label | Meaning |
| --- | --- |
| **Draft** | Status written in Figma, shown unchanged. |
| **Not documented** | Figma says nothing about this, and the portal does not fill the gap. |
| **Proposed — needs review** | Added by the portal (behaviour, API, wording) and waiting for a decision. |
| **Portal implementation** | Code written for this site from Figma, not a production contract. |
| **Source discrepancy** callouts | The Figma documentation and the live component disagree. The page says which one the portal follows. |

## Run locally

Requires Node.js 20 or newer.

```bash
npm install
npm run dev        # http://localhost:5180
```

On macOS you can also double-click `start-portal.command` (if present). It installs dependencies on the first run,
starts the server and opens the browser. Keep the Terminal window open while you use the site.

Other scripts:

```bash
npm run build      # regenerate tokens + type check + production build into dist/
npm run preview    # serve the production build
npm run tokens     # regenerate tokens and glyphs from tokens/source/
npm run typecheck
```

Do not keep the project in an iCloud-synced folder (Desktop or Documents with iCloud Drive on). When iCloud offloads
files, `node_modules` breaks.

## Tech stack

Vite, React, TypeScript, React Router, MDX and lucide-react. Fonts: DM Sans and Orbitron (from Fontsource) for the
components; system UI fonts for the portal shell.

Storybook is not used. There is no production component code to document yet, so a custom portal with isolated
previews was simpler. Examples use a Storybook-like shape (args, controls, render), so Storybook can be added later
if it is needed.

## Project structure

The layers are kept separate on purpose:

| Layer | Folder | Rule |
| --- | --- | --- |
| Portal UI | `src/portal/` | The site shell (Apple-inspired, system fonts). It never styles BaaS components. |
| Tokens from Figma | `tokens/source/` → `src/tokens/generated/`, `public/tokens/` | Generated by `scripts/build-tokens.mjs` and `scripts/build-glyphs.mjs`. Never edit the generated files by hand. |
| Design system components | `src/ds/` | Implemented from Figma and styled only with the generated `var(--…)` tokens. |
| Component registry | `src/registry/` | One entry per Figma page: name, status, Figma node, properties. Navigation, catalog, search and coverage are generated from it. |
| Documentation | `src/docs/<figma-page>.mdx` | Text from the Figma documentation frames, restructured. |
| Examples | `src/examples/` | Controls, render function, code snippet and variant matrix per component. Synthetic data is in `data.ts`. |
| Preview frame | `preview.html`, `src/preview/` | A separate document that loads only BaaS fonts, tokens and component CSS. |

**Preview isolation.** Every live preview is an iframe on `preview.html`. The portal and the frame exchange
`postMessage` events (`args`, `surface`, `ready`, `height`). Portal CSS cannot leak into a preview, and modals and
dropdowns stay inside their frame.

**Routing.** `/`, `/components`, `/components/<figma-page>`, `/foundations/<section>`. Sections and tokens have stable
anchors, for example `#variants-and-states` or `#token-surface-control`. Catalog filters live in the query string.
When hosting, serve `index.html` for unknown paths (SPA fallback).

## Deployment (GitHub Pages)

`.github/workflows/deploy.yml` builds the site and publishes it on every push to `main`. One-time setup: in
**Settings → Pages → Build and deployment → Source**, choose **GitHub Actions**. The site is then served at
`https://<owner>.github.io/<repository>/`; progress and errors are in the **Actions** tab.

The workflow builds with `BASE_PATH=/<repository>/` (read by `vite.config.ts`) so that all links, previews and token
downloads work under the sub-path, and copies `index.html` to `404.html` so deep links and refresh work. Locally the
base path stays `/`.

A GitHub Pages site of a public repository is public. Do not publish real customer data; all sample data in the
portal is synthetic.

## Updating from Figma

Updates are **manual**; nothing syncs automatically.

1. Run the read-only extraction scripts in `scripts/figma-extract.md` against the Figma file (through the Figma MCP
   connector or a plugin console). Replace `tokens/source/figma-variables.txt`, `figma-styles.json` and
   `figma-glyphs.txt`.
2. Run `npm run tokens`, then review the diff of `public/tokens/tokens.css`. The script fails on a broken alias or a
   duplicate name.
3. For a component change, update its entry in `src/registry/components.ts` (variants, properties, status), the
   implementation in `src/ds/`, the example in `src/examples/`, and the text in `src/docs/`.
4. Run `npm run build` and compare the "Variants and states" matrix with the Figma component set.

### Adding a component page

1. Add the component to `src/registry/components.ts`, using its Figma page name as the slug.
2. Implement it in `src/ds/` using only token variables, and export it from `src/ds/index.ts`.
3. Add its example (defaults, controls, render, code, matrix) to `src/examples/` and register it in `src/examples/index.ts`.
4. Write `src/docs/<figma-page>.mdx`. Mark gaps with `<NotDocumented />` and portal additions with `<Proposed />`.
5. Set `built: true` on the registry entry.

## Known limitations and open items

- No production package exists. All component APIs on the site need developer validation before anyone relies on them.
- Six foundation pages (Typography, Dimensions, Radius, Borders and opacity, Gradients, Shadows and glass) are plain token tables for now.
- Several translucent tokens are drawn opaque in Figma, because the paint opacity there is 100%. The portal follows the token value. This is flagged on the affected pages.
- Discrepancies between Figma documentation and components are listed in `docs/stage-3-notes.md` and on each page.
