## Anatomy

Read from the component set:

- **Box** — 24 × 24 px, corner radius `radius/xs` (4 px).
- **Glyph** — a Lucide icon instance, 14 × 14 px, centred, 1 px stroke. `check` when checked, `minus` when indeterminate. Absent when unchecked.

There is no label layer. The checkbox is a bare control; where its label comes from is <NotDocumented />.

Hover, pressed, focus-visible, disabled, error and read-only states are <NotDocumented />. They are not drawn in Figma and are not implemented in the portal, with one exception described under [Accessibility](#accessibility).

## Behaviour

<NotDocumented /> in Figma. The preview uses the native checkbox convention so the control can be tried: clicking or pressing Space on `unchecked` or `indeterminate` gives `checked`; on `checked` it gives `unchecked`. Indeterminate can only be set by the parent. This is <Proposed />.

## Accessibility

<NotDocumented /> in Figma.

In this portal the component wraps a native `input type="checkbox"`, so it is focusable, toggles with Space, and reports checked, unchecked and mixed states to assistive technology.

Verified gaps:

- **No focus state is designed.** So that keyboard users can see focus in the preview, the portal draws the system's 1 px `border/focus` ring with a 2 px offset. This ring is <Proposed />.
- **No disabled or error state is designed.**
- **No label.** Each use must supply an accessible name.
- The glyph stroke is 1 px at 14 px, which is heavier than the Icon rule of size ÷ 24. Whether that is intended is not stated.
