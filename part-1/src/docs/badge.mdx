## Anatomy

StatusBadge is a horizontal auto-layout pill: height `size/label/*`, padding 4 / 10 (12 for lg), gap 4, radius full, fill `status/*-bg`.

- **Label** — always text, colour `status/*-text`. It can be renamed on every instance.
- **TrailingIcon** — an Icon instance, size sm. Hidden by default (`showIcon` = false). Its colour variant follows the appearance.

Not interactive: no hover, pressed or focus states. The status is expressed by the appearance.

## Appearances

| appearance | Used for |
| --- | --- |
| `positive` | Completed, Active, +18% |
| `warning` | Pending, +12% |
| `danger` | Failed. Marked INFERRED in Figma (from tokens and the old library) |
| `info` | Inherited (KYC) |
| `neutral` | Role tag "Sub-user · active" |
| `accent` | Countdown "Expires in 04:47" |
| `awaiting`, `processing` | <NotDocumented /> The variants exist in the set; the tokens are described as awaiting and processing pill colours. |

## Sizes and width

| size | Height | Text style | Padding |
| --- | --- | --- | --- |
| `sm` | 24 | `typography/caption` | 10 |
| `md` | 28 | `typography/body-sm` | 10 |
| `lg` | 32 | `typography/body-lg-strong` | 12 |

Width hugs the label by default. In tables the badge is set to Fill inside a fixed-width status cell (for example 104 px on the Users screen) and the label stays centred. That is a layout choice of the parent, not a component property.

## Usage

| Screen element | Appearance · size | Settings |
| --- | --- | --- |
| Status Completed / Pending (transactions table) | positive / warning · md | no icon |
| Delta +18% / +12% (metric cards) | positive / warning · lg | icon `trending-up` |
| Status Active (Users table) | positive · md | Fill in a 104 px cell |
| KYC Inherited (Users table) | info · md | Fill in a 104 px cell |
| Role tag (Users table) | neutral · sm | hug |
| Countdown (Confirm payment modal) | accent · sm | hug |

## Accessibility

From Figma: the status is always written as text, never colour alone. Contrast of text on its own fill: positive 6.3:1, warning 6.1:1, danger 5.6:1 (4.5:1 needed). "Info, neutral and accent pairs are still to be measured. Screen-reader behaviour needs implementation validation."

Verified gap: the awaiting and processing pairs are not measured either.
